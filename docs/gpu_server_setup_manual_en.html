Ubuntu 24.04.4 LTS Server ASUS ProArt X870E-CREATOR RTX PRO 6000 Ada (48GB) vLLM v0.28.0 + Qwen3.8-27B

GPU Server Standalone Setup Manual (NVIDIA / Docker / vLLM)

A standardized production setup guide for configuring the ASUS ProArt X870E motherboard with a single NVIDIA RTX PRO 6000 Ada (48GB VRAM) system, mirroring the proven driver and vLLM optimization stack from our dual-GPU environment.
1

Prerequisites and System Inspection

Immediately after a fresh Ubuntu 24.04.4 Server installation, install build tools required for kernel module builds (DKMS) and network utilities:

sudo apt update && sudo apt upgrade -y
sudo apt install -y build-essential dkms curl wget git jq net-tools pciutils

PCIe Slot Detection

Verify that the RTX PRO 6000 GPU installed in the PCIe 5.0/4.0 slot is properly recognized on the bus:

lspci -nnk | grep -iE 'vga|3d|nvidia'
2

NVIDIA Driver Installation (v580 Open Kernel Module)

Install the stable nvidia-driver-580-open package from the official Ubuntu 24.04 LTS repository (consistent with driver version 580.173.xx):

# 1. Install NVIDIA open kernel module driver
sudo apt install -y nvidia-driver-580-open

# 2. Enable Persistence Mode service (keeps driver resident in VRAM)
sudo systemctl enable --now nvidia-persistenced

# 3. Reboot to load the newly built kernel modules
sudo reboot

Verify Driver Status After Reboot

Reconnect via SSH and verify driver status:

nvidia-smi
Verification Checklist: • Driver Version: 580.173.xx
• Memory-Usage: 49140MiB (~48GB VRAM detected)
• Persistence-M: On
3

Docker Engine and Docker Compose Installation

Install Docker Engine and Compose v2 packages, and grant necessary user permissions:

# 1. Install packages
sudo apt install -y docker.io docker-compose-v2

# 2. Add current user to docker group
sudo usermod -aG docker $USER

# 3. Enable and start Docker service
sudo systemctl enable --now docker

# 4. Apply new group to current shell session
newgrp docker
docker --version && docker compose version
4

NVIDIA Container Toolkit Installation & Docker Integration

Configure the NVIDIA Container Toolkit so that Docker containers can directly access the host GPU:

# 1. Register GPG key
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | \
  sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg

# 2. Register APT repository list
curl -s -L https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list | \
  sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' | \
  sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list

# 3. Update index and install toolkit
sudo apt update
sudo apt install -y nvidia-container-toolkit

# 4. Register Docker runtime and restart daemon
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker

GPU Passthrough Smoke Test

docker run --rm --gpus all ubuntu nvidia-smi
Success Criteria: The container output matches the host RTX PRO 6000 nvidia-smi display.
5

vLLM Container Deployment & Execution (Qwen3.8-27B)

RTX PRO 6000 (48GB) Optimization Advantage:
• Dual RTX 5070 Ti (16GB × 2) setups require strict TP=2 splitting and careful memory boundaries.
• RTX PRO 6000 provides a massive 48GB VRAM pool on a single card. Using --tensor-parallel-size 1 eliminates PCIe inter-GPU communication overhead, unlocking peak throughput and easily accommodating 16K–32K context windows with abundant KV cache.

5.1 Create Working Directory & Environment File (.env)

mkdir -p ~/docker-runtime/vllm
cd ~/docker-runtime/vllm

cat <<'EOF' > ~/docker-runtime/vllm/.env
# Hugging Face Token (optional for public models)
HF_TOKEN=

# Prevent PyTorch VRAM fragmentation (essential for stable CUDA Graph capture)
PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True
EOF

chmod 600 ~/docker-runtime/vllm/.env

5.2 Create docker-compose.yml

cat <<'EOF' > ~/docker-runtime/vllm/docker-compose.yml
services:
  vllm-qwen:
    image: vllm/vllm-openai:v0.28.0
    container_name: vllm-qwen3.8-27b
    runtime: nvidia
    restart: unless-stopped
    ipc: host
    ports:
      - "8000:8000"
    env_file:
      - .env
    volumes:
      - ~/.cache/huggingface:/root/.cache/huggingface
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: all
              capabilities: [gpu]
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
      interval: 30s
      timeout: 10s
      retries: 30
      start_period: 600s
    command: >
      --model cyankiwi/Qwen3.8-27B-AWQ-INT4
      --served-model-name qwen3.8:27b
      --tensor-parallel-size 1
      --gpu-memory-utilization 0.92
      --max-model-len 16384
      --max-num-seqs 16
      --max-num-batched-tokens 8192
      --kv-cache-dtype fp8
      --enable-chunked-prefill
      --enable-prefix-caching
      --reasoning-parser qwen3
      --port 8000
      --host 0.0.0.0
EOF

5.3 Launch vLLM & Monitor Logs

# Start container in background
docker compose up -d

# Inspect startup logs & weight loading
docker compose logs -f

When the line Uvicorn running on http://0.0.0.0:8000 appears, the server is ready. (Press Ctrl + C to exit logs)

Operational Checklist (ASUS ProArt X870E & OS)

Category Check Item Recommended Setting / Solution
BIOS Above 4G Decoding Enabled (Essential for 48GB VRAM address space mapping)
BIOS Re-Size BAR Support Enabled or Auto (Optimizes direct VRAM access)
Storage Root Partition LVM Capacity Default Ubuntu Server installs may limit root partition to 100GB.
sudo lvextend -l +100%FREE /dev/ubuntu-vg/ubuntu-lv && sudo resize2fs /dev/ubuntu-vg/ubuntu-lv
Firewall External Traffic (UFW) Allow incoming port 8000 for network access:
sudo ufw allow 8000/tcp
